# Правила работы над A45

- Не менять дизайн, который предоставил пользователь: композицию, размеры, отступы, цвета, шрифты, иконки и оформление элементов. Менять дизайн только по прямому запросу пользователя. Функциональные исправления должны сохранять существующий внешний вид.

## Обязательная единая система компонентов

- Единый источник цветов, шрифтов, размеров компонентов, меню, окон, отступов и скруглений — `design-tokens.css`. Справочник и правила применения — `docs/DESIGN-SYSTEM.md`. Не добавлять отдельные HEX/RGB/HSL-цвета в другие CSS, HTML или JS и не подбирать новые оттенки локально.
- Однотипные кнопки, иконки, поля, меню, окна, вкладки, тултипы и состояния должны использовать один общий компонент и общие токены на всём сайте: в публичной версии, редакторе и формах. Исправление общего элемента делается в его исходном компоненте, а не отдельным патчем для конкретной страницы.
- Кнопки действий — `actionButton()` / `ui-button`; только общие варианты `primary` и `outline`. Кнопки-иконки — `iconButton()`. Размеры, шрифт, границы, цвета, hover/focus/disabled/loading задаются централизованно. Для одного и того же варианта размеры и поведение везде одинаковы.
- Иконки — исключительно официальный набор Lucide React через `scripts/generate-icons.mjs`, `src/ui/icons.mjs` и `window.A45Icons`. Одна библиотека, единая толщина линий и общий набор размерных вариантов. Не подключать второй набор иконок, не рисовать SVG и не заменять иконки символами.
- Контекстные меню действий — общий `ui-action-menu`: единые ширина, отступы, радиус, строки и состояния. Для окон и полей использовать общую семью компонентов. Допустимы только именованные размерные варианты и адаптивные правила из системы токенов, обоснованные содержимым; локальные случайные размеры запрещены.
- Утверждённый пользователем макет является эталоном. Унификация не означает новый дизайн. Единственное окно фотографий, PDF и документов — `openMediaDialog()` с восстановленным фото-макетом; менять его только по прямому запросу пользователя. Скачивание есть только у документов, у фотографий его нет.
- Перед созданием нового элемента проверить `src/ui/components.mjs` и существующую систему. Если нужного варианта нет, расширить общий компонент и добавить токен/описание, затем применять его во всех однотипных местах. Не копировать разметку и стили общего компонента в страницу и не накапливать локальные переопределения.
- При изменении общего компонента проверять все места его использования, просмотр и редактирование, адаптивность, длинные названия/описания, hover/focus/disabled/loading/error. Проверка `tests/design-system.mjs` входит в сборку. Не объявлять унификацию завершённой без проверки фактической интернет-версии.

- Все кнопки с одной иконкой (стрелки, закрытие, меню, плюс, перемещение, скачивание) используют единый квадратный hit-area: ширина равна высоте, скругление 16 px, прозрачный фон в покое и одинаковый светло-серый hover. Эталон стрелок — скриншот пользователя от 24.10.2026: тонкий Lucide chevron, без растягивания SVG и без прямоугольной подложки. Не менять эти параметры локальными стилями; проверять публичный просмотр и редактор. Иконки внутри текстовых кнопок и пунктов меню не имеют отдельной подложки.

## Остальные правила

- Подготовка к публикации: по запросу пользователя от 23.10.2026 подключаем существующий вход администратора для серверного редактирования. Публичный просмотр остаётся без входа.
- Для создания проекта, раздела и подраздела обязательно только непустое название. Описание и фото необязательны. При отсутствии фото использовать заглушку на карточке, сохраняя дизайн формы загрузки.
- На интернет-доменах создание/редактирование выполняется только после проверки настоящего администратора через RLS и is_a45_admin. Сохранение проектов, фотографий и разделов выполняется только в Supabase и на localhost, и в интернете. Локальные примеры и fallback в localStorage не используются рабочим приложением; старые данные доступны только для переноса. Не обходить RLS и не выдавать администраторские права анонимным посетителям.

- Старый глобальный режим визуального редактирования с плавающей панелью «A45 / Режим редактирования / Предпросмотр / Сохранить / Завершить / Выйти» удалён по запросу пользователя. Не возвращать панель, её обработчики и зависимости. Создание карточек и отдельный редактор проекта должны работать независимо.

- Кнопка «Редактировать» остаётся на каждой странице: на главной редактирует разделы, на странице раздела/подраздела включает выбор карточки с муравьиной дорожкой; клик по проекту открывает модальное окно карточки (название, обложка, описание), сохраняя текущий список, клик по карточке подраздела — его модальное окно; только кнопка «Редактировать» внутри открытого проекта открывает редактор его табов и блоков. Удаление старой плавающей панели не означает удаление контекстных кнопок или логики редактирования.

- Новый редактор проекта — единый inline canvas для создания и редактирования: название и блоки правятся на месте, при наведении показываются плюс и ручка; вкладки под названием используют общее модальное окно создания/редактирования. Старый document-sidebar, библиотеку фотографий и отдельные формы блоков не возвращать. Во вкладке фотографий нужна дроп-зона со статусом каждого файла.

- Единая бесплатная библиотека иконок — Lucide (https://lucide.dev/icons/). Использовать только официальные иконки из src/ui/icons.mjs (генерация scripts/generate-icons.mjs), для обычных страниц — window.A45Icons. Не рисовать SVG вручную и не заменять иконки Unicode-символами. Повторяемые элементы брать из src/ui/components.mjs и ui.css: iconButton, editorTools, photoDropzone, actionItem. Расширять общий компонент вместо копирования разметки.
- Все дроп-зоны сайта используют только uploadDropzone() / photoDropzone(), bindDropzones() и стили .ui-dropzone в ui.css. Эталон — присланный пользователем дизайн формы создания карточки (пунктирная рамка, скругление, единая оранжевая кнопка из системы компонентов). Не создавать локальные варианты оформления в styles.css/admin.css. Различаться могут только подписи, число файлов и реальные ограничения загрузки.
- Если на странице или в открытом диалоге есть дроп-зона, при перетаскивании файлов подсвечивается весь экран; файл можно бросить в любой точке. Использовать единый installPageDrop из src/ui/page-drop.mjs, не добавлять локальные обработчики с дублирующей загрузкой.

- Во вкладке «Фотографии» редактора должна быть одна дроп-зона, затем компактный список файлов с миниатюрой и лоадером/зелёной галочкой. Готовая строка целиком открывает карусель по клику и подсвечивается при наведении; удаление готовой фотографии находится только в карусели. Ошибочные/незавершённые загрузки можно отменить из списка. Не выводить большие фотографии, отдельные дроп-зоны каждого IMAGE/GALLERY-блока или надпись «Готово к сохранению». Плюс добавления блоков остаётся внизу.

- Главная, левое меню и «Перенести в раздел» используют только текущую структуру навигации. Список назначений брать из window.A45Navigation.categories(), не из всех серверных/демонстрационных categories. Старые ID остаются только для совместимости сохранённых проектов, но не должны возвращаться в меню, на главную или в список переноса. Не дублировать корневые разделы по одинаковым названиям.

## Единый алгоритм вложений для всех проектов

- Все существующие и новые проекты используют один `editorView`, `uploadDropzone`/`photoDropzone`/`documentDropzone`, `bindDropzones` и `installPageDrop`. Никаких проверок ID/названия проекта и отдельных обработчиков загрузки для отдельных проектов.
- Назначение вкладки определяется только `src/ui/tab-kind.mjs`: «Фото», «Фотографии», «Фото и видео», Photos используют один фото-компонент; документы — один компонент документов. Сохранённый тип медиа-вкладки сохраняется после переименования. Гидратация, создание, отображение и сериализация используют один resolver.
- Во вкладке вложений: одна дроп-зона + одна кнопка выбора, перетаскивание файлов в любую точку страницы, приоритет открытого модального окна, единая очередь и статусы загрузки, список прикреплённых файлов, единое окно просмотра/редактирования/удаления. После Save и перезагрузки вложения остаются в той же вкладке.
- Обязательная регрессия: новый и существующий проект; все поддержанные названия фото-вкладки, включая «Фото и видео»; повторное открытие/переименование/сохранение типа; загрузка через кнопку, дроп-зону и вне неё. Одной записи правила недостаточно: проверять общий компонент и путь событий.
