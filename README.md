# A45 — персональная творческая библиотека

Персональная творческая библиотека. Frontend собирается через esbuild; иконки Lucide React преобразуются в SVG при сборке.

Запуск из этой папки:

```sh
python3 -m http.server 3000 --bind 127.0.0.1
```

Открыть http://127.0.0.1:3000. Если порт занят, выберите другой, не останавливая чужой сервер.

- `index.html` — общая структура.
- `styles.css` — адаптивное оформление и сетка карточек на CSS Grid.
- `app.js` — hash-навигация, дерево, фильтры, представления. `repository` — точка замены локального источника данных.
- `data/projects.js` — 7 направлений и 17 проектов; поля id, title, description, categoryIds, year, type, image, content, gallery.
- `assets/` — локальные SVG-заглушки.

Маршруты: `#/`, `#/projects`, `#/about`, `#/category/0`, `#/category/0/Макросъёмка`, `#/project/0-0`, `#/year/2026`.
Фильтры пересекаются с текущим разделом и сохраняются при переходах до сброса. Главная всегда показывает все направления; фильтры доступны на внутренних страницах и сохраняют условия для списков материалов. Годы в дереве открывают архив всех работ за год. Escape закрывает фильтр; Tab удерживается внутри модального окна нативным dialog.


## Категории и связи проектов

Категории хранятся плоским массивом `categories`. Обязательные поля: `id`, `parentId`, `title`, `slug`, `description`, `sortOrder`. Корни имеют `parentId: null`; порядок соседей задаёт `sortOrder`. `image` у корневых категорий используется на главной. Идентификаторы уникальны; родитель должен существовать, циклы недопустимы. Глубина в интерфейсе не ограничена; дерево строит одна рекурсивная функция `treeNodes`.

```js
{ id: 'insects', parentId: 'wildlife', title: 'Насекомые',
  slug: 'insects', description: 'Наблюдения', sortOrder: 0 }
// Проект может принадлежать любым категориям, включая разные ветки:
categoryIds: ['insects', 'apps', 'editing']
```

Старые `placements` заменены на `categoryIds`; дублировать родителей в массиве не требуется. Страница родительской категории включает собственные публикации и публикации всех потомков, без повторных карточек. Проект «Макросъёмка насекомых» привязан только к `insects`, но виден также в `wildlife`, `macro` и `photography`. «Умная камера» по-прежнему относится к веткам IT, технического творчества и видео.

Маршруты категорий: `#/category/photography`, `#/category/macro`, `#/category/insects`. Числовые старые ссылки и прежние ссылки с названием подраздела поддерживаются для совместимости. В публикации параметр `?category=insects` сохраняет категорию для хлебных крошек и возврата. В дереве только текст: название категории с детьми — кнопка раскрытия без перехода и изменения URL. В каждой такой ветке первым идёт ссылка «Все проекты» на страницу категории. Название листовой категории — обычная ссылка. Иконок и линий вложенности нет; уровни различаются отступами, активный пункт выделен мягким фоном. Состояние раскрытых веток и позиция меню сохраняются при переходах и фильтрации в рамках открытой вкладки. При открытии глубокого раздела раскрываются все предки. Закрытые ветки исключены из фокуса через `inert`; анимация учитывает настройку уменьшения движения.

Фильтр направлений показывает корни; фильтр подразделов — всех потомков с полным путём, независимо от глубины. Условия направления и подраздела проверяются по одной ветке. Год и тип материала работают совместно с иерархией.

Проверки: `node A45-New/tests/archive.cjs` из родительской папки.

## Компактный интерфейс

В шапке — логотип (переход на главную) и «Обо мне». Главная сразу показывает карточки без вводного блока и фильтра. Общий шаблон списков категорий, подразделов, проектов и архива по годам содержит хлебные крошки, заголовок и кнопку фильтра в одной строке, затем карточки. Описание раздела, надзаголовок, разделитель и счётчик убраны. Полное описание проекта сохранено в публикации.

CSS Grid использует 5 колонок от 1440px, 4 от 1024px, 3 от 768px, 2 от 480px и 1 ниже 480px. Эти же пороги действуют в контентной области внутренних страниц справа от дерева. Промежутки — 16px. У всех карточек изображения 4:3 с `object-fit: cover`; индивидуальных пропорций нет. В карточке только изображение, название и описание максимум в две строки с многоточием. Высота зависит от длины названия, карточки располагаются по строкам без masonry.


Левая панель на desktop использует `position: sticky` и собственный ограниченный по высоте scroll-контейнер; основной документ прокручивается отдельно. Раскрытие меняет только DOM ветки, без перерисовки страницы, изменения hash или сброса scroll. На мобильных дерево открывается поверх контента; фиксация body блокирует фон и сохраняет его позицию. Закрыть меню можно текстовой кнопкой или Escape. Переход по ссылке закрывает мобильное меню; при повторном открытии его позиция сохраняется.

## Универсальная страница проекта

`project-page.js` содержит `ProjectPage`, `ProjectTabs`, `FileList` и `buildTelegramPublication(project, url)`. Проекты используют один шаблон; все данные находятся в `data/projects.js`.

Демонстрационный проект: `http://127.0.0.1:3000/#/project/camera-crane`.
Прямая ссылка на вкладку: `#/project/camera-crane?tab=history`. Дополнительный параметр `category` сохраняет контекст возврата. Старые ID проектов продолжают работать, новые ссылки могут использовать `slug`.

В проекте предусмотрены `slug`, `publishedAt` (ISO-дата), `image`, `categoryIds`, `files`, `tabs` и `telegram`. У каждой вкладки поля `id`, `title`, `type`, `sortOrder`, `content`. Обзор всегда первый; остальные вкладки сортируются по `sortOrder`. У разных проектов разные вкладки. Если обзор не задан, компонент создаёт его из краткого описания.

Формат `content`:

- `text`: `{ heading?, paragraphs: [...], steps?: [...] }` — безопасный обычный текст.
- `gallery`: `{ images: [{ src, alt, caption }] }`.
- `video`: `{ src, poster?, caption? }` — локальное HTML5-видео с controls.
- `files`: `{ files: [{ id, name, type, size, url }] }`, `size` в байтах.
- `mixed`: массив `{ type, content }`; блоки могут быть text, gallery, video, files, image (`{ src, alt, caption }`), specs (`{ title, items: [[название, значение]] }`).

Вкладки используют History API, ссылки сохраняются после перезагрузки и при переходах назад/вперёд. При смене вкладки обновляется только панель, дерево не перерисовывается. Чтобы браузер не сдвигал страницу при открытии более короткого материала, панель сохраняет минимально необходимую высоту до нижней границы текущего экрана. Навигация вкладок поддерживает Tab, стрелки, Home и End; на телефоне список прокручивается горизонтально.

Галерея открывает полное изображение в нативном dialog; закрытие — кнопкой или Escape. Превью 4:3, полное изображение использует `object-fit: contain`. Чертежи представлены текстовыми пояснениями, схема — SVG-иллюстрацией, инструкция — TXT, общий комплект — ZIP. Файлы реальны и лежат в `assets/files`; техническими документами для изготовления они не являются. `assets/demo-motion.mp4` — трёхсекундное локальное тестовое видео H.264, без внешних сервисов.

`telegram: { enabled, title, description, image, publicationStatus }` готовит метаданные будущей публикации. Кнопка «Поделиться» открывает Telegram Share URL с текущей ссылкой, включая вкладку. Функция формирования текста не отправляет сообщения. Автопубликация потребует отдельного серверного механизма; токенов, бота и Bot API в прототипе нет. Локальная ссылка 127.0.0.1 будет доступна получателю только на компьютере, где запущен этот сайт; публичная отправка ссылки станет полезной после размещения сайта.

Проверки страницы: `node A45-New/tests/project-page.cjs`. Доступ к управлению браузером в этой среде отсутствует: автоматические проверки покрывают данные, шаблоны и маршрутизацию с моделью DOM, но не заменяют визуальную проверку и реальное нажатие «Назад» в браузере.

## Публикация через GitHub и Vercel

- Репозиторий: https://github.com/AlexErkovich/A45-New
- Production: https://a45-new.vercel.app
- Операторский кран: https://a45-new.vercel.app/#/project/camera-crane
- История создания: https://a45-new.vercel.app/#/project/camera-crane?tab=history
- Проект Vercel: `family-tree-page/a45-new` (отдельный от FamilyTreePage).

Production-сборка: `npm run build`; она запускает проверки и копирует только разрешённые frontend-ресурсы в `dist/`. Внешних зависимостей нет. Vercel использует Framework Preset **Other**, Install Command `npm ci --ignore-scripts`, Build Command `npm run build`, Output Directory `dist`. Настройки находятся в `vercel.json`. Каталог `dist` не коммитится. `.env*`, `.vercel` и ключи исключены из Git и загрузки Vercel. На сервер публикуется содержимое `dist`, поэтому README, тесты и настройки сборки не доступны как ресурсы сайта.

Роутер остаётся hash-based: `/#/project/camera-crane?tab=history`. Сервер получает путь `/`, поэтому прямые ссылки и перезагрузка не требуют SPA rewrite. Не заменяйте их на `/project/...` без отдельной доработки роутера. Telegram Share URL использует `location.href`, поэтому на опубликованном сайте содержит публичный домен и активную вкладку.

После подключения репозитория в Vercel Settings → Git ветка Production Branch должна быть `main`. Стандартная Git-интеграция выполняет публикацию каждого нового коммита в `main`; GitHub Actions не нужны. Обновление:

```sh
cd /Users/a45/Desktop/A45/A45-New
npm run build
git add .
git commit -m "Описание изменений"
git push origin main
```

Проверяйте завершение в Vercel → a45-new → Deployments. При отсутствии связи с GitHub включите приложению Vercel доступ именно к этому репозиторию и подключите его в Settings → Git. Резервный ручной запуск из связанной папки: `vercel deploy --prod` (нужен авторизованный Vercel CLI).

Индивидуальные Telegram-превью проектов пока не реализованы: Telegram не выполняет клиентский JavaScript и не использует hash для выбора серверной страницы. Для разных превью понадобится статическая генерация отдельных HTML с Open Graph метаданными либо серверная обработка маршрутов. Текущая кнопка отправляет корректную ссылку на выбранный проект/вкладку, без бота и токенов.

## Подготовленная интеграция Supabase и админка

Работа находится в отдельной локальной ветке `feature/supabase-category-admin`; в production не опубликована. Пошаговая настройка, границы проверки и миграции описаны в [docs/SUPABASE-SETUP.md](docs/SUPABASE-SETUP.md).

`src/cloud-entry.js` собирает официальный Supabase SDK и административный редактор в `integration.js`; `src/category-service.mjs` содержит операции категорий, проверку изображений и общую геометрию кадрирования. Конфигурация берётся только из SUPABASE_URL и SUPABASE_PUBLISHABLE_KEY (либо SUPABASE_ANON_KEY). При отсутствии конфигурации сайт сохраняет локальные данные.

Миграции в `supabase/migrations` не копируются в `dist` и не применяются при сборке. `tests/database.mjs` проверяет их в одноразовом локальном PostgreSQL; реальная облачная интеграция требует отдельной проверки перед production. Маршруты админки — `/admin` на Vercel и `/#/admin` для обычного статического локального сервера.

Старый глобальный режим визуального редактирования и его плавающая панель удалены. Создание карточек и отдельный редактор проекта работают независимо.

## Автоматическая оптимизация фотографий проектов

Локально добавлены оригиналы до 30 МиБ, Worker/WebP thumbnail/content/large и повторное использование снимка для обложки. Схема, проверки, ограничения и порядок подготовки миграции 004 описаны в [docs/IMAGE-OPTIMIZATION.md](docs/IMAGE-OPTIMIZATION.md). Перед облачной проверкой требуется отдельно применить проверенную миграцию в тестовой базе; production не изменён.

## Главная страница и локальные изменения разделов

Главная использует плитку карточек, Space Grotesk и Inter. Режим редактирования выделяет карточки неподвижной точечной рамкой толщиной 1 px. Добавление и редактирование раздела поддерживает загрузку и перетаскивание обложки, предпросмотр, проверку обязательных полей и подсказки без сдвига формы. Удаление раздела требует подтверждения; доступно восстановление.

Изменения разделов на главной, включая добавление и удаление, сохраняются в `localStorage` текущего браузера (`a45-home-drafts`). Они не записываются в Supabase и не синхронизируются между устройствами. Загруженные облачные обложки продолжают отображаться. Удаление карточки не удаляет материалы и файлы из облачного архива.

Общий компонент `feedback.js` показывает сообщения рядом с полями, а также действия сохранения и выхода. Заголовок окна раздела закреплён при прокрутке.
