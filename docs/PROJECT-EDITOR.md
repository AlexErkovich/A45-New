# Редактор новых проектов A45-New

Подготовлен локально. Миграция 003 не применена к Supabase, сайт на Vercel не обновлялся.

## Что добавлено

- В режиме редактирования администратора на странице любой категории: «+ Создать проект». Переход `/project/new?category=technical` автоматически выбирает исходную категорию.
- Отдельный редактор `/project/new`, список `/project/drafts`, продолжение `/project/edit/<UUID>`.
- Основная категория и любое количество дополнительных в рекурсивном дереве. Одна запись проекта; категории/родители показывают её без дубликатов.
- Черновик по умолчанию, явная публикация с подтверждением, снятие с публикации. Кнопка сохранения опубликованного проекта сохраняет публичную версию; кнопка черновика явно снимает её с публикации.
- Обязательная первая вкладка «Обзор», остальные: добавление, название, порядок, удаление с подтверждением. Публичные ссылки вкладок используют стабильные ключи.
- Блоки TEXT, HEADING, IMAGE, GALLERY, VIDEO, FILE, LIST. Перестановка/удаление, подписи, галереи с порядком. VIDEO открывает HTTP(S)-ссылку; загрузка собственных видео пока не реализована.
- Текст: абзацы, **жирный**, *курсив*, `[ссылка](https://example.com)`, списки `- пункт`. HTML всегда экранируется; ограниченная Markdown-разметка преобразуется безопасно.
- Обложка: JPG/PNG/WebP до 5 МБ, настройка масштаба и положения 4:3, отдельный оригинал и WebP-кадр 1200×900 плюс параметры кадрирования. Оригинал не доступен посетителям. Галереи — до 5 МБ на изображение. Документы — до 20 МБ; PDF/ZIP проверяются по сигнатуре, неизвестные документы сохраняются как binary download; HTML/SVG/исполняемые расширения отклоняются.
- Пример шлема заполняет только текущую несохранённую форму, с подтверждением замены. Ничего автоматически не публикуется и характеристики не выдумываются.

## Схема и безопасность

Новая миграция `supabase/migrations/003_projects.sql` создаёт пять таблиц: `projects`, `project_categories`, `project_tabs`, `project_blocks`, `project_media`. Существующие категории, ID, связи и демонстрации не переносятся и не изменяются.

`save_a45_project(doc, expected_revision)` проверяет защищённую функцию `is_a45_admin()`, блокирует одновременную запись и сохраняет снимок в транзакции. Прямая запись через REST запрещена даже администратору — используется только проверенный RPC. Несовпадение версии отклоняет запись; введённое остаётся в форме. Slug генерируется один раз как `p-<UUID>` и не меняется при переименовании. URL не конфликтуют с существующими демонстрациями.

Bucket `project-media` закрытый. RLS проверяет доступ администратора или опубликованную ссылку на конкретный файл из обложки/блоков того же проекта. Неиспользуемые и подготовленные файлы остаются закрытыми даже при редактировании опубликованного проекта. Ограничительные Storage-политики защищают от существующих слишком широких политик других bucket. Старые файлы автоматически не удаляются.

Нет публичных или подписанных ссылок на файлы черновика. Клиент скачивает файл через авторизованный Storage API и создаёт временный Blob URL для текущей страницы. После снятия с публикации новые скачивания запрещены; уже скачанные пользователем файлы отозвать невозможно. Blob URL живёт только в текущем браузере; для распространения используется постоянная ссылка проекта, а не Blob URL.

Сохранение с новыми файлами: зарегистрировать метаданные под черновиком/предыдущим опубликованным снимком → загрузить неизменяемые UUID-файлы → атомарно сохранить новый снимок. Сбой загрузки сохраняет старое публичное содержимое, данные формы и возможность повторить попытку. Новый проект может остаться техническим черновиком после частичного сбоя; опубликованным он не станет. Не удаляйте его файлы вручную до завершения повторной попытки.

## Следующий шаг — только после подтверждения

1. Сохранить резервную копию production-базы доступным в аккаунте способом. Открыть правильный проект Supabase A45-New.
2. В SQL Editor выполнить **только чтение** `supabase/manual/06_projects_preflight.sql`. Проверить 45 категорий, 7 корней, одного администратора; отсутствие пяти новых таблиц и bucket `project-media`. При неожиданном результате остановиться.
3. После отдельного подтверждения выполнить целиком `003_projects.sql`. При ошибке остановиться; транзакция откатится, существующую схему не подменять.
4. Выполнить `supabase/manual/07_verify_projects.sql`. Пять RLS включены, bucket private, 20 MiB, anon не может вызвать save RPC, 45 категорий сохранены.
5. Новые ключи не нужны: используются существующие `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY` из игнорируемого `.env.local`. Секреты/service_role не нужны. Публичная регистрация остаётся отключённой.

## Локальная проверка после миграции

`npm run build`, затем `npm run preview`; открыть http://127.0.0.1:3001/login и войти существующим администратором. На странице технического творчества включить редактирование, нажать «Создать проект».

Заполнить название, категории, обложку → применить кадр, добавить вкладки и блоки, открыть предпросмотр, сохранить черновик. В «Проекты и черновики» открыть его повторно. В приватном окне убедиться, что черновик/его файлы не читаются. Для проверки публикации использовать собственный тестовый проект, а не автоматически пример шлема. После явной публикации проверить обе категории, глубокую ветку, прямую ссылку вкладки и скачивание документа; снять с публикации и повторить анонимную проверку.

Публикация в БД влияет на будущие клиенты этой БД сразу; production-frontend на Vercel сейчас не обновляется и новые таблицы не использует. Деплой — отдельный шаг после проверки и подтверждения.

## Проверено и ограничения

`npm run build` включает проверки существующих маршрутов, дерева, карточек/фильтров, отдельный PostgreSQL (PGlite) с RLS и Storage-политиками, DOM-тесты редактора, загрузки/ошибки/повтор, сборку с официальным SDK и фиктивным HTTP. Записи в production при тестах не выполняются.

Фактический вход администратора, загрузка в Supabase и мобильный вид в настоящем браузере требуют проверки после одобренной миграции: доступа к управлению браузером в этой сессии нет. Адаптивные стили подготовлены, но DOM-тесты не подтверждают визуальную точность на устройстве. Автосохранения в браузерное хранилище нет: до успешного сохранения данные существуют только в памяти вкладки, с предупреждением при уходе. Индивидуальные серверные Open Graph-превью Telegram не добавлялись.
