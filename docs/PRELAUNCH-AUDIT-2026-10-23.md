До переноса теплицы проверены семь опубликованных серверных проектов и 36 записей медиа: недоступных вариантов content не обнаружено. Эта проверка не заменяет визуальную оценку каждого оригинала.

У локальной «Макроохоты на насекомых» есть дополнительная запись фотографии `photo_2025-09-02_01-44-22.jpg` без локального оригинала. Для подтверждения переноса этой версии нужен исходный файл. Перенос останавливается при отсутствии оригинала, не удаляя локальную копию.

## Что проверено положительно

- `npm run build`: весь набор тестов, сборка и запуск полученного приложения в Happy DOM с подменённой HTTP-границей.
- Проверки PostgreSQL/PGlite: административные права, RLS, конфликты версий, связи категорий и проектов, безопасное удаление из текущего каталога, повторное применение миграции.
- Проверки загрузок: частичный сбой/повтор, общий выбор файлов, подсветка всей страницы, приоритет открытого диалога, состояния загрузки и ошибок.
- Проверки редактора и просмотра: общий компонент карусели, локальное сохранение, контекстное редактирование карточки и содержимого.
- `git diff --check`: ошибок пробелов нет.
- Проверка production-зависимостей npm audit: известных уязвимостей не обнаружено на момент проверки.
- Иконки Lucide установлены локально, генерируются из официальных компонентов; лицензия включена в assets/licenses.
- Секретный service-role ключ не требуется клиенту; `.env.local` не отслеживается Git. В клиентской конфигурации только публичный ключ Supabase.
- Заголовки публикации: запрет MIME sniffing, ограничение Referrer, запрет iframe-встраивания, перепроверка HTML-кэша.

## До публикации

1. Проверить перенос оставшейся версии «Макроохоты», исключив фотографию без оригинала по указанию пользователя.
2. Разобрать старые демонстрационные проекты: сохранить нужные пользовательские тексты и вложения, не переносить лишние примеры автоматически. Подготовить перенос SVG без ослабления запрета произвольных SVG-загрузок.
3. Проверить внешние превью ссылок облачных проектов: статические share-страницы покрывают включённые в сборку примеры, но не все новые облачные проекты.
4. Проверить вход, выход, обновление страницы проекта, загрузку и сохранение уже на целевом HTTPS-домене, включая Supabase Site URL/redirect URLs.
5. После проверки состава изменений — GitHub и затем развёртывание. Полная готовность к публикации не заявляется, пока пункты выше не закрыты.

Миграции на сервер применены через авторизованный SQL Editor; пользовательские проекты и файлы при этом не удалялись. В базе временный режим подтверждён значением `enabled = false`.

## Обновление: только серверное сохранение

По прямому требованию пользователя рабочий клиент больше не подключает локальный адаптер проектов и временный режим создания. Это относится и к localhost, и к production. Старые локальные записи используются только страницей переноса; сообщения об успешном сохранении появляются после серверного commit. Удаление проекта также выполняется на сервере без локального скрытия при отказе.

Перенос сохраняет исходный идентификатор в серверных метаданных, чтобы старые ссылки продолжали открывать проект. Встроенные SVG-иллюстрации преобразуются в WebP, а SVG-вложение схемы переносится в ZIP без разрешения произвольных SVG-загрузок. Старые блоки сохраняются в совместимом TEXT-контейнере без потери содержимого.

Добавлена проверка: заполненный localStorage не превращает подтверждённое серверное сохранение в ошибку; пропускается только согласованный отсутствующий файл. Полная проверка данных выполняется по завершении пакетного переноса обоих браузерных адресов.
