# Редактор проекта: документ и вкладки

Редактор открывается по прежним адресам `/project/new` и `/project/edit/:id`. Слева — вкладки проекта с числом блоков. Справа — название и описание проекта, текущая вкладка и её блоки. Год и категории находятся в сворачиваемых свойствах. «Обзор» остаётся обязательным первым разделом.

## Основные действия

- Создать вкладку: «+ Новая вкладка». Курсор сразу переходит в её название. Меню «•••» позволяет менять порядок и удалять вкладку.
- Добавить текст: выбрать блок «Текст». Поле растёт по содержимому. В пустом текстовом блоке `/` открывает выбор типа текущего блока. Можно добавлять заголовки, списки, фото, галереи, ссылки на видео и файлы.
- Загрузить сразу несколько фото: выбрать нужную вкладку и нажать «Загрузить фотографии в …» либо перетащить файлы в редактор. Создаётся галерея именно в этой вкладке. При ошибке уже подготовленные фотографии остаются в ней.
- Убрать фото из галереи: открыть «Действия с фото» → «Убрать из галереи». Фотография остаётся в панели фотографий и других вкладках.
- Перенести фото: «Действия с фото» → выбрать вкладку. Для переноса целого блока есть выбор вкладки под блоком. Перенос убирает исходное вхождение.
- Панель «Фотографии»: показывает все снимки проекта и названия вкладок/обложку, где каждый используется. Можно выбрать несколько, добавить в текущую вкладку, использовать как обложку или убрать из всего проекта.
- «Убрать из проекта» требует подтверждения и убирает все вхождения снимка и его использование как обложки. Сам файл в Storage не удаляется.
- Удаление блока, снимка, вкладки и перенос можно отменить кнопкой «Отменить действие» в верхней панели. Это отмена последнего действия; новая правка текста сбрасывает эту возможность, чтобы не потерять последующие изменения.

## Сохранение

Автосохранения в облако нет: верхняя панель показывает несохранённые изменения. «Сохранить» сохраняет текущий статус, включая опубликованный проект. «Опубликовать» и «Снять с публикации» — отдельные действия. После подтверждённой записи открывается просмотр с сообщением об успехе. Несохранённые данные защищены предупреждением при уходе; при ошибке остаются в памяти вкладки.

## База данных

Для сохранения удаления фотографии из панели после перезагрузки подготовлена миграция `005_project_media_reconcile.sql`, после 004. Прежняя функция сохранения только добавляла media-записи, поэтому исключённые из документа снимки возвращались после загрузки с сервера. Новая функция в той же транзакции удаляет исключённые metadata-записи только данного проекта, только если они больше не используются в блоках и обложке. Физические объекты Storage не удаляются. Политики и права доступа не расширяются.

Миграция проверена в PGlite, включая повторный запуск, сохранность Storage-объектов и закрытие доступа к исключённому снимку. К облачной базе не применялась. До её применения удаление из галереи и переносы сохраняются прежним механизмом, но исключённый из панели снимок может вновь появиться в списке после перезагрузки.

## Проверки

- `npm run build`: регрессии, контекст массовой загрузки, перенос снимка, выбор и удаление из панели, отмена, `/`-команды, сохранение/просмотр, миграция 005.
- `node tests/project-editor-browser.mjs`: реальный Chrome с тестовыми данными, desktop 1440 px и mobile 390 px, вкладки, панель фотографий и отсутствие горизонтального переполнения. Не подключается к Supabase.

Новые зависимости не добавлялись. Production, Vercel и физические оригиналы не менялись.
