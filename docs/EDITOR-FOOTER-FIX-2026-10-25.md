# A45-New: сброс редактирования и служебный footer

Исправлено только локально относительно опубликованного коммита `a389de2`. Коммит, git push и деплой в этой задаче не выполнялись. Supabase production не запрашивался и не изменялся. Дизайн и разметка карточек сохранены.

## Точная причина

В `home-page.js` обработчик `#home-edit` был зарегистрирован на document в capture-фазе, до capture-обработчика проверки роли, который устанавливается в `A45Cloud.start()`.

Порядок одного физического клика:

1. Первый capture-обработчик немедленно выполнял `editing = !editing`: режим включался, появлялись «Готово» и рамки.
2. Следующий capture-обработчик останавливал исходное событие и асинхронно проверял пользователя/`is_a45_admin`.
3. При положительном ответе он помечал кнопку `accessChecked` и выполнял `button.click()` для разрешённого действия.
4. Этот повторный клик снова попадал в обработчик главной страницы и повторно выполнял `editing = !editing`: режим выключался.

Задержка между переключениями соответствовала асинхронной проверке доступа. Это не случайное снятие роли Supabase и не сброс переменной при маршрутизации. На старом собранном бандле добавленная регрессия воспроизвела ошибку: режим менялся ещё до завершения проверки роли.

## Исправление

Обработчик действий главной переведён в bubble-фазу. Теперь capture-обработчик доступа перехватывает исходный клик до переключения состояния. Только одобренный повторный клик доходит до обработчика действия и переключает режим один раз. Проверки роли, RLS и защита маршрутов не отключены. Таймеры, принудительное включение и повторная установка editing не добавлены.

Дополнительно проверено, что повторная отрисовка той же страницы, завершение загрузки категорий, редактирование/сохранение названия и описания, создание новых DOM-элементов карточки и обновление шапки сохраняют включённый режим. Кнопка «Готово» явно выключает его. В разделе проверено сохранение `listingEditKey` и состояния кнопки после повторной отрисовки.

## Служебные ссылки

Один компонент `renderManagementNavigation()` создаёт блок `#management-navigation.ui-management-nav` в существующем footer после допуска администратора внутри `/admin`:

- «Обо мне» → `/admin#/about`;
- «Просмотр сайта» → `/`;
- «Черновики» → `/admin#/drafts`;
- «Данные и перенос» → `/admin#/transfer` — сохранена одна исходная ссылка, поскольку это один существующий экран;
- «Выйти» → прежняя операция Supabase signOut.

В шапке эти пункты удалены. Кнопки «Редактировать», «Готово» и «Добавить» остаются в исходных блоках шапки. При выходе в публичный просмотр, завершении сессии и потере допуска служебный блок удаляется из DOM. Компонент не создаёт дубликатов при повторном вызове.

Небольшое правило footer делает блок доступным также на главной, в разделе и в редакторе, где прежние стили скрывали весь подвал. Плотность и шрифт используют общие токены; ссылки переносятся по строкам. Это не CSS-скрытие административных ссылок для посетителей — в публичном DOM блока нет.

## Проверки

- До исправления: новая регрессия на существующем production-бандле завершилась ожидаемой ошибкой `home edit must wait for access check`.
- После исправления: `npm run build` — все 16 ограниченных последовательных шагов прошли. БД/PGlite и Chrome в набор не входят.
- Отдельно усиленная регрессия удерживала мок-RPC роли незавершённым: до ответа режим оставался выключенным; после ответа включался один раз и сохранялся после обновлений/сохранения. Проверена ошибка проверки роли без включения режима.
- Проверены служебные ссылки, однократный вызов выхода, отсутствие дубликатов и правильное CSS-отображение footer для home/listing/editor. Реальный визуальный просмотр в браузере не выполнялся.
- Production-бандл с официальным SDK проверен с полностью подменённым HTTP: вход, создание проекта, редактирование текста, одна крошечная фотография с мок-кодеком, Save/повторное открытие, публичный просмотр и выход. Проверка не является авторизацией на production.
- Реальные HTTP-запросы проверяли только временный localhost-сервер: `/`, `/login`, `/admin`; он закрыт после проверки.
- `git diff --check` прошёл. Файлы миграций Supabase не менялись.

Ограничения: V8 old heap 256 МиБ, RSS всей группы 512 МиБ, 60 секунд на шаг, 600 секунд на набор, вывод 64 КиБ. Измеренный максимум полного ограниченного запуска — 153 МиБ; усиленная регрессия — 142 МиБ. После каждого шага контроллер подтвердил очистку дочерних процессов. RSS контролируется периодическим опросом.
