# Разделение публичного просмотра и управления A45

Отчёт первого этапа до разрешения на сборку. Актуальные результаты production-сборки и ограниченных проверок: [PUBLICATION-READINESS-2026-10-25.md](PUBLICATION-READINESS-2026-10-25.md).

На первом этапе изменения были только в локальных исходниках. Git push, деплой, обращения к Supabase production и применение SQL не выполнялись. Полный набор тестов, PGlite, Chrome и production-сборка не запускались. Существующие dist/integration.js не являются проверенным результатом этих изменений: новый бандл намеренно не собран.

## Поведение

| Адрес | Доступ и поведение |
| --- | --- |
| `/`, `/#/category/...`, `/#/project/...` | Только публичный просмотр даже при сохранённой сессии администратора |
| `/login` | Существующая форма Supabase Auth по email/паролю; после проверки `is_a45_admin` — `/admin` или защищённый адрес возврата |
| `/admin`, `/admin#/category/...`, `/admin#/project/...` | Те же компоненты страниц и карточек; инструменты только после проверки администратора |
| `/admin#/project/new?category=...`, `/admin#/project/edit/...?tab=...` | Существующий редактор с сохранением контекста категории и выбранной вкладки |
| `/admin#/drafts`, `/admin#/transfer` | Только проверенный административный контекст |
| Старые `/project/new`, `/project/edit/...`, `/project/drafts`, `/transfer` | Нормализация в защищённый маршрут; они не дают публичного доступа к редактору |
| Выход | Supabase signOut, сброс режима/приватных снимков, возврат на `/`; ошибка выхода сохраняет текущую сессию и показывает сообщение |

Прямые ссылки карточек/вкладок/логотипа внутри управления сохраняют `/admin`, включая открытие в новой вкладке. «Просмотр сайта» открывает публичный `/`. URL возврата после логина проверяется на тот же origin; небезопасный/некорректный адрес заменяется на `/admin`.

## Где изменён код

- `src/access-routes.mjs`, `src/session-navigation.mjs`: единые адреса и безопасный возврат после входа.
- `src/management-access.mjs`: проверка роли, выход, потеря сессии, блокировка запоздавших ответов авторизации, обработка ошибки проверки без выдачи доступа.
- `src/public-client.mjs`, `src/cloud-entry.js`: отдельный клиент чтения без хранения сессии, с отдельным storageKey; публичные категории/проекты и медиа читаются с публичными правами. Изменяющие операции API приложения требуют административного контекста, затем сервисы повторно проверяют роль и сервер применяет RLS.
- `app.js`, `home-page.js`: управление создаётся условно в DOM; на публичном сайте нет кнопок, редактирующих обводок и формы управления. На публичной главной очищается скрытое дерево. Приватные снимки проектов и запоздавшие загрузки черновиков не переходят в публичный просмотр. Прямая ссылка на черновик после перезагрузки загружает его отдельно только после проверки администратора. Быстрый переход между вкладками не обходит смену контекста доступа.
- `src/project-editor.mjs`, `src/project-editor-view.mjs`: тот же редактор под `/admin`; закрытие и Save остаются в управлении; прямой вызов mount на публичном маршруте ничего не меняет. Логика вкладок/блоков/вложений сохранена.
- `src/transfer-page.mjs`: доступ только в управлении; поздняя загрузка страницы переноса не заменяет публичный экран.
- `vercel.json`, `scripts/preview.mjs`: локально подготовлена доставка общего index.html для `/admin`. Настройки Vercel на сервере не менялись.
- `index.html`: новая версия URL ресурсов для будущей сборки.

CSS, структура карточек, дизайн, миграции и производственные данные не изменены этой задачей. Второй экземпляр сайта не создан.

## RLS: границы подтверждения

Проверены локальные SQL-источники миграций 001, 003–008:

- Роль администратора определяется по `auth.uid()` и закрытой `private.site_admin`.
- Для категорий включена RLS; публичное чтение учитывает опубликованность категории и её предков; обновления требуют администратора.
- Для projects и связанных категорий/вкладок/блоков/медиа включена RLS. Опубликованные проекты читаются публично, остальные — администратором.
- Прямые права записи в проектные таблицы у anon/authenticated отозваны; запись через `save_a45_project` требует `is_a45_admin`.
- Создание/публикация категорий и сохранение навигации проверяют администратора.
- Storage ограничивает чтение проектных файлов доступностью опубликованного проекта/зарегистрированных производных изображений, запись — администратором. Restrictive guard ограничивает возможные широкие разрешающие политики.

Это статический аудит исходников, а не исполнение SQL. Он не доказывает, что production имеет именно эти миграции и не содержит дополнительных политик/прав. Состояние production необходимо отдельно проверить только чтением перед публикацией; никаких производственных изменений не подготовлено к автоматическому применению.

## Безопасные проверки

`npm run check:admin-safe` запускает только синтаксис и маленькие локальные сценарии с моками. Используются внешний контроллер, 256 МиБ V8 old heap, 512 МиБ RSS группы, 60 секунд на шаг, 600 секунд на набор, 64 КиБ вывода и последовательный запуск. После каждой проверки контролируется отсутствие живых дочерних процессов. DOM-дампы запрещены.

Проверены: публичный DOM, вход и серверная роль на моках, отказ неадминистратору, выход/ошибка выхода, потеря сессии, поздний ответ роли и черновиков, защищённый редактор и ссылки, сохранность несохранённых полей при входе, один маленький текстовый черновик с ошибкой Save и повтором. Реальные запросы авторизации/сохранения/загрузки файлов и отрисовка в настоящем браузере не выполнялись.

Измеренный максимум RSS среди выполненных лёгких проверок — 105 МиБ; финальная проверка текстового Save — 100 МиБ. Это пиковые значения периодических измерений, а не жёсткая гарантия отсутствия кратких всплесков между замерами.
