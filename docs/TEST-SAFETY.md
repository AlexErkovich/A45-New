# Безопасный запуск проверок A45

После сообщения о зависании MacBook Air M1 и показании около 44 ГБ изменён механизм запуска. Точная причина системного сбоя/фиолетового экрана не установлена. Обнаруженная генерация больших assertion diff была риском, но сама по себе не доказывает причину перезагрузки macOS.

## Ограничения по умолчанию

| Ресурс | Ограничение |
| --- | --- |
| V8 old heap каждого Node, наследующего NODE_OPTIONS | 256 МиБ |
| V8 semi-space | 8 МиБ |
| Сумма RSS всех живых процессов группы | 512 МиБ |
| Время одной проверки, включая сборку | 60 секунд |
| Время всего набора | 600 секунд |
| Совокупный stdout/stderr одной проверки | 64 КиБ |
| Одновременные проверки | 1 на рабочую копию |
| Core dump | Отключён |

Контроллер написан на Python 3 и находится вне event loop тестового Node. RSS проверяется через `/bin/ps` примерно каждые 50 мс плюс время системного запроса. Это контроль с периодическим опросом, а не жёсткая квота macOS: кратковременное превышение возможно. V8 heap не включает ArrayBuffer, WebAssembly, нативные библиотеки и Chrome, поэтому нужен отдельный контроль RSS всей группы. Встроенный процесс V8 при исчерпании heap может завершиться раньше RSS-порога.

Тяжёлые проверки могут не уложиться в консервативные ограничения. В таком случае набор останавливается; автоматического повторного запуска или увеличения лимита нет.

## Запуск

До отдельного разрешения пользователя полный набор, сборку, БД и Chrome не запускать.

- `npm run check:list` — только список проверок и лимитов, без запуска.
- `npm run check:safety` — только маленькие искусственные сценарии ограничителя; без приложения, PGlite, Chrome и сборки.
- `python3 scripts/check-safety/run.py tests/имя.mjs` — одна проверка под контролем.
- `npm test` — полный набор из манифеста, последовательно, под контролем.
- `npm run build` — ограниченный набор без PGlite/Chrome, production-компиляция, проверки бандла, мок-входа/редактирования и localhost HTTP; всё последовательно под контролем. `npm run build:full` сохраняет полный прежний набор с БД и требует отдельного разрешения.
- `python3 scripts/check-safety/run.py tests/image-optimizer-browser.mjs` — отдельная тяжёлая проверка Chrome, только с разрешения. В обычный набор не добавлена.

Прямой `node tests/...` обходит внешний контроллер и запрещён правилами проекта. Требуются Python 3, Node.js и доступ к `/bin/ps`. Если чтение процессов запрещено песочницей, контроллер завершится до запуска теста. Прежние NODE_OPTIONS заменяются защитными, чтобы случайно не наследовать большой heap или сторонний preload.

## Вывод и ошибки

`preload.cjs` устанавливается до импорта тестов. Сравнения equal/strictEqual проверяют значения без создания Node AssertionError с diff. Глубокие строгие сравнения используют `isDeepStrictEqual` и при несовпадении создают короткую ошибку без actual/expected. Не используемые проектом нестрогие структурные сравнения запрещены: применять `node:assert/strict`.

Объекты в console не инспектируются: выводится короткий маркер. Строки ограничены 2000 символами, сообщения ошибок — 1200 символами, стек — шестью короткими строками. Внешний контроллер дополнительно ограничивает общий поток, включая прямую запись в stdout/stderr и аварийные сообщения V8. Он не хранит неограниченный лог в памяти.

Не передавать DOM в глубокие сравнения: даже без diff обход DOM может быть дорогим. Сравнивать идентичность элементов или примитивы: `assert(element === expected)`, `assert.equal(element === null, true)`, textContent/число элементов/атрибут.

## Дочерние процессы и аварийная остановка

Каждая проверка запускается в отдельной Unix process group/session. При тайм-ауте, превышении RSS/вывода, ошибке или сигнале остановки контроллер завершает всю группу: SIGTERM, затем при необходимости SIGKILL. Следующая проверка не начинается до проверки очистки. Завершившийся тест с живыми дочерними процессами считается ошибкой; оставшиеся процессы принудительно завершаются.

Preload запрещает detached у Node child_process API. Существующий Chrome-тест использует обычный spawn; сборка может запускать esbuild. Их процессы входят в ту же группу. Не добавлять обходы через setsid, демонизацию или отдельные сессии.

Блокировка в системной временной папке не допускает второй контроллер для этой рабочей копии. После SIGKILL самого контроллера или выключения Mac блокировка может остаться; её нельзя автоматически удалять, не проверив, что прежний запуск завершён. Никакая очистка в пользовательском процессе не гарантируется при выключении компьютера или SIGKILL самого контроллера.

## Что подтверждает самопроверка

Маленькие временные сценарии проверяют фактический heap cap, короткие ошибки сравнений, тайм-аут зависшего event loop, остановку по низкому RSS-порогу (без выделения большого объёма памяти), ограничение вывода, запрет detached, завершение оставленного дочернего процесса и отказ параллельному запуску. Проверка очистки касается созданных сценариями процессов. Она не устанавливает, остались ли старые процессы от предыдущего системного сбоя, и не заменяет будущую разрешённую проверку реальных тестов.
