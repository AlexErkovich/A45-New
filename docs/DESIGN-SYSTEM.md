# Единая система оформления A45

Это обязательный порядок работы с интерфейсом. Правила закреплены в [AGENTS.md](../AGENTS.md). Эталонные макеты пользователя сохраняются при любых функциональных изменениях.

## Источники

| Область | Единственный источник |
| --- | --- |
| Цвета, шрифты и размеры | [design-tokens.css](../design-tokens.css) |
| Общие стили компонентов | [ui.css](../ui.css) |
| Публичные экспорты компонентов | [src/ui/components.mjs](../src/ui/components.mjs) |
| Текстовые кнопки | [src/ui/buttons.mjs](../src/ui/buttons.mjs) |
| Иконки Lucide React | [scripts/generate-icons.mjs](../scripts/generate-icons.mjs), генерируемые `src/ui/icons.mjs` и `window.A45Icons` |
| Просмотр фото, PDF и документов | [src/ui/media-dialog.mjs](../src/ui/media-dialog.mjs) |
| Автоматическая проверка | [tests/design-system.mjs](../tests/design-system.mjs) |

`styles.css` и `admin.css` описывают страницы и размещение элементов. Они используют токены, а не собственные палитры. В них нельзя создавать локальные версии общих кнопок, меню, окон или иконок.

## Цвета

Сначала использовать смысловую роль: `--color-accent`, `--color-accent-hover`, `--color-accent-soft`, `--color-page`, `--color-surface`, `--color-field`, `--color-heading`, `--color-text`, `--color-muted`, `--color-icon`, `--color-divider`, `--color-border`, `--color-success`, `--color-error`, `--color-warning`, `--color-info`.

Остальные существующие оттенки собраны там же в группы `palette-neutral`, `palette-warm`, `palette-green`, `palette-cool`, `palette-effect`. Они сохранены точно, чтобы перенос цветов не изменил утверждённый вид сайта. Это совместимость действующих стилей, а не разрешение подбирать отдельный оттенок для каждой новой страницы. При дальнейшем объединении компонентов заменять такие обращения общей смысловой ролью в исходном компоненте.

Прозрачность, цвет теней, затемнение подложки и состояния элементов также берутся из токенов. `transparent`, `currentColor`, `inherit` допустимы как поведение CSS. Палитра не применяется к содержимому фотографий, пользовательских документов и фирменным изображениям.

## Компоненты и размеры

| Семейство | Варианты и токены |
| --- | --- |
| Кнопка действия | `actionButton()`, `ui-button--primary` / `ui-button--outline`; общие `--ui-button-height`, `--ui-button-radius`, `--ui-button-padding`, `--ui-button-font` |
| Кнопка-иконка | `iconButton()`, `--ui-control-size`, `--ui-control-radius`; Lucide без ручных SVG и Unicode-подмен |
| Меню действий | `ui-action-menu`, `--menu-width`, `--menu-padding`, `--menu-radius`, `--menu-row-height`, `--menu-row-padding`, `--menu-icon-size` |
| Диалог ввода | Именованные `--dialog-sm-width`, `--dialog-form-width`, `--dialog-form-padding`, `--dialog-form-radius`; размер выбирается по задаче, а не по странице |
| Окно файлов | `openMediaDialog()`, `--media-width`, `--media-radius`, `--media-columns`, `--media-preview-ratio`, `--media-preview-radius`, `--media-layout-*` |
| Загрузка | Общие `uploadDropzone()` / `photoDropzone()` / `documentDropzone()`, `bindDropzones()` и `installPageDrop()` |

Однотипные компоненты имеют одинаковые размеры, цвета, скругления и поведение на всём сайте. Различия допустимы только как явно названные варианты общего компонента и адаптивные правила. Меню выбора категории, короткая форма ввода и просмотр большого файла не обязаны иметь одинаковую ширину: это разные задачи, но общие цвета, типографика, элементы управления и правила взаимодействия.

Заголовки используют `--font-heading`, основной текст — `--font-body`. Нельзя подключать вторую библиотеку иконок или задавать произвольные толщины/размеры в отдельной странице. Размерные варианты иконок задаются централизованно для роли: меню, кнопка, тип файла или крупная иллюстрация дроп-зоны.

## Окно файлов — утверждённый макет

Сохраняется фото-макет пользователя: широкий предпросмотр слева, узкая панель справа, стрелки по бокам кадра, центрированные миниатюры под ним, поля названия и описания справа. Фото, PDF и документы используют один компонент. Различаются содержимое предпросмотра и допустимые действия. Скачивание — только у документов; у фотографий его нет. Обложка — только у изображений в редакторе. Общие правила закрытия, клавиатуры, подтверждения удаления, ошибок и загрузки одинаковы.

## Порядок каждого изменения

1. Найти существующий компонент и токены; сначала переиспользовать их.
2. Если нужен вариант, добавить его в общий компонент и описать здесь, затем применить ко всем однотипным местам.
3. Не копировать разметку и не перекрывать общий стиль локальной правкой. Менять источник компонента.
4. Проверить просмотр и редактор, длинный текст, маленький экран и состояния hover, focus, disabled, loading, error.
5. Выполнить обязательные проверки и проверить фактическую публикацию. Не выдавать описание правил за завершённую унификацию непроверенных частей.

`tests/design-system.mjs` включён в сборку: он запрещает буквальные цвета вне файла токенов и проверяет подключение токенов, базовые размеры и использование общего меню. Любые исключения должны быть осмысленными и не отменять утверждённые пользователем макеты.
